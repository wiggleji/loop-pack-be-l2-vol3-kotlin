# notes
# - 양쪽 모두 300k 까지도 sub-second — TOP-N=100 으로 결과 cardinality 고정 + filesort + LIMIT push-down.
# - 100k → 300k 구간에서 chunk 와 tasklet 의 격차가 1.4× → 1.16× 로 좁아짐.
#   더 큰 데이터셋 (수백만 row + score 컬럼 인덱스 부재) 에서는 추월할 가능성 있음.
# - chunk 는 fetch(JdbcCursor) → process → JpaItemWriter 의 3단계 파이프라인이라 base cost 가 높지만,
#   chunk 단위 회복 가능성·중간 상태 관측가능성 등 운영성에서 우위.
# - 50k 이상 시드는 ProductMetricsSeeder 가 JdbcTemplate.batchUpdate(chunk 1000) 로 fallback —
#   seed 자체는 측정 대상이 아님 (launchJob wall time 만 캡처).
